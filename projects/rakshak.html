01 / THE PROBLEM

Start with a clear question.

The work was about turning a challenge brief into a usable interface with distinct roles and clear report-oriented tasks. I contributed to the UI in a collaborative project context.

02 / DESIGN DECISIONS

Role-aware navigation

Make the key paths for different user roles understandable.

Readable report screens

Give important report details structure and hierarchy rather than presenting one dense wall of text.

Team delivery

Coordinate UI decisions with the broader project concept and other contributors.

In-progress status

Keep unfinished flows distinct from completed screens; the project should not be represented as a deployed service.

WHAT I TOOK AWAY

  • ✳A polished screen still needs a coherent workflow behind it.
  • ✳Role-based products require careful navigation decisions.
  • ✳Team projects make naming and shared assumptions matter quickly.

03 / NEXT ITERATION

What I’d improve next.

Complete and test the main role journeys, then validate the screens against the team’s agreed functional scope.
